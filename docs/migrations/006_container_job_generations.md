# Bounded offline container whole-job generations

Apply this additive schema only with the existing explicit `arcentra-cli migrate --conf <reviewed-config>` command after backing up the selected database. Controller startup never migrates it. This change creates no credentials, grants, runtime privileges, network access, or approval permissions.

New JobRun fields are `retry_plan` (bounded canonical MEDIUMTEXT), `retry_plan_digest` (VARCHAR(67)), `current_generation_id` (VARCHAR(64)), and `current_generation` (integer). Defaults remain empty/zero. The controller captures the complete retry policy, all preallocated StepRun identities, and a digest of the executable dispatch before queueing. Generic repository writes cannot replace this plan or mutate a captured retry job. Captured retry attempts and committed receipts cannot be removed through the generic/public step-deletion API.

New StepRun fields are `generation_id`, `generation_binding_digest`, and `retryable_shell_exit` (default false). The latter is an explicit trusted-Agent declaration included in the committed protobuf terminal receipt. A permitted exit code alone is insufficient to authorize another generation.

The new `job_run_generation` table has a unique generation ID and a unique `(job_run_id, number)` pair. Each row stores immutable admission request/descriptor bindings and a once-written exact successor transition receipt. The current generation pointer, prior closure, and successor admission are committed atomically. At most the original approved 2–5 generations can be admitted. Original JobRun claim, task/source/runtime v1 digests, input-manifest digest, and preallocated attempt IDs retain their existing meaning.

There is no backfill. Existing dispatches cannot acquire retry authority, and legacy terminal observations do not become generation or cleanup evidence. Finish or cancel in-flight jobs with their original compatible Agent before upgrading. New retry-enabled jobs require the controller and Agent protocol together, explicit operator opt-in, and advertised Agent capability. Unsupported RPCs fail closed. At this migration's initial implementation stage, approval-bearing container retry jobs were rejected. V17 subsequently added [exact-content `whole_job` approval](../pipeline/retry-approval.md) with [migration 007](007_retry_approval_binding.md) and separate default-off operator policies; it does not authorize approval-bearing `failed_step` retry. That later combination has a separate [V19 exact contract](../pipeline/failed-step-retry-approval.md), reusing migrations 005–008 without migration 009 and requiring independent acceptance and default-off operator permissions.

Generation 1 has one narrowly scoped preparation phase: its admission may bind an empty input-manifest digest only while the original manifest is still unknown. The already-frozen retry definition binds the complete dispatched source and artifact inputs. The immutable generation binding is never rewritten after checkout. `PreparationOnly=true` describes this bootstrap; `ExecutionAllowed` permits the current uninterrupted worker to prepare a session, not to bypass command admission. Every step RUNNING transaction independently requires the authoritative pinned original manifest, a live original claim/Agent/pipeline, the current generation, and an elapsed retry delay. The first such transaction activates the generation. Every successor permanently binds the exact nonempty original manifest digest. A command-free initial generation may finish successfully while still preparing only when the inputs are pinned and every exact current-round attempt has a committed SKIPPED receipt; skip timestamps alone are not RUNNING evidence.

Advancement requires the exact committed pure shell-failure receipt, all previous-round terminal receipts with the remainder skipped, remaining attempt budget, and a canonical cleanup receipt for the prior controller-issued runtime claim. The receipt identifies the exact session, container, snapshotter/snapshot, owner digest, and workspace device/inode; it records verified absence of processes and owned resources. It is trusted-Agent evidence, not independent remote attestation. The backend creates no independent lease, so no lease-removal claim is invented.

Identical lost-ACK transition requests return the same generation. Changed requests fail closed. Historical exact terminal receipts remain acknowledgeable but never authorize commands. A first cancellation receipt must bind the current generation, including when it is aborted; started steps must also match their stored generation. Unstarted future slots may close under the current generation without acquiring execution claims. Before admission, only empty generation evidence is valid. Artifacts can be registered only from successful current-generation attempts through the authenticated final publication transaction. Read-only generation inspection always returns `ExecutionAllowed=false`, including after restart. No descriptor or journal replay authorizes automatic command continuation across an Agent restart.

Verification includes SQLite transaction/concurrency and migration fixtures, full authenticated gRPC lost-ACK/reopen and revocation cases, and the existing disposable MySQL/container acceptance lanes. The real acceptance fixture also checks both cancellation/handoff transaction orders using clearly labeled synthetic protocol rows on its existing MySQL connection and authenticated TLS client, without extra runtime sessions. The same assertions have a separate SQLite control test; neither synthetic cleanup receipts nor local tests claim real container or MySQL acceptance.

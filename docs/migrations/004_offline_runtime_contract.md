# Offline runtime contract schema upgrade

The implementation-level offline runtime passed [hosted run 38508866022](https://github.com/arcentrix/arcentra/actions/runs/38508866022) at PR head `e7132be275c144a2eadc03b61e3c4f16dd302c4e` (tested merge `12e6cd81e2ca6f79bb5967f457aa6b3f377b1a9d`). That run kept the compiled gate false. The separate gate-on candidate must still verify ordinary production configuration and worker entry points; that result is pending. Both operator policies remain disabled by default. A schema migration never opts in execution. See [evidence, full runtime configuration and opt-in sequence](../offline-runtime-acceptance.md).

This change uses the existing explicit `arcentra-cli migrate --conf /path/to/config.toml` operator migration. Do not run a migration automatically on service startup. Back up the database and validate a representative copy before using the migration.

Additions:
- `agent.runtime_capabilities`: nullable JSON, supplied only by credential-validated Agent registration or authenticated heartbeat. Missing old reports permit legacy baremetal selection only. Explicit execution mode is recorded independently of readiness: an unready containerd Agent is never selected for baremetal work. Unknown or malformed modes are excluded from all execution. An old heartbeat clears stale readiness; user labels do not grant runtime capability.
- `job_run.runtime_type`, `runtime_image`, `runtime_cpu`, `runtime_memory`, `runtime_binding_digest`: non-null strings with empty defaults. Historical rows retain baremetal semantics; do not backfill fabricated runtime evidence.

The controller atomically stores the image digest, resource limits, original Agent identity and source expectation before dispatch. Generic updates cannot change the runtime columns. Runtime jobs require the exact recomputed binding digest on the initial execution claim and subsequent reports. An older Agent that ignores the payload field cannot claim a runtime job. Legacy single-step fetch/stream interfaces exclude runtime jobs entirely, and runtime step claims are transactionally bound to the original running parent claim. The recovery inspection RPC is authenticated, read-only and restricted to the exact original Agent/job/claim/binding identity.

The accepted first-profile implementation is `containerd-offline-v1`: exactly one complete Agent job, an explicitly allowlisted `image@sha256` reference, mandatory positive CPU and memory hard limits bounded by operator maxima, and no runtime config flags. Shell steps accept only an empty action or `run`. Artifact downloads form a prefix; shell steps form the middle; artifact uploads form a suffix. HTTP/native/deployment steps, host paths, standalone tasks and automatic retry are rejected. A retry requires a new run and fresh isolated workspace.

Fresh disposable SQLite tests cover additive defaults, capture/claim ownership and read-only recovery confirmation. The hosted whole-job test additionally exercised fresh disposable MySQL runtime persistence. Representative existing-data MySQL migration, locking/collation compatibility and backup/restore remain operator validation responsibilities. Never downgrade by dropping evidence while runtime jobs or recovery records remain unresolved.

The single-job profile does not support upstream artifact-input DAGs, automatic retries, online package installation, arbitrary deployment/plugins, or a hostile multi-tenant security guarantee. The runtime journal binds the client FIFO root path and filesystem identity; preserve that exact private root across restart. Do not replace or delete journals/FIFO state as a schema-upgrade shortcut.

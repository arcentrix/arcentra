# Durable exact-content retry approval (explicit opt-in)

Apply this additive schema only using the existing explicit `arcentra-cli migrate --conf <reviewed-config>` command, after backup and review. Controller startup does not migrate. Migration 006 remains unchanged. No migration enables runtime/approval operator flags, creates credentials, grants access, or starts execution. Real MySQL and container acceptance remain required before enabling this feature.

PipelineRun adds immutable `retry_approval_context` MEDIUMTEXT and `retry_approval_context_digest` VARCHAR(67). Empty legacy contexts remain empty; no actor, policy, or authority is inferred. A dedicated run-creation operation captures the authenticated manual actor, exact resolved definition identity, exact sorted gated job set, and finite operator policy. Generic run creation and context updates cannot insert or replace these fields.

JobRun adds `retry_approval_required` (false default), `retry_approval_id` VARCHAR(64), and `retry_approval_evidence_hash` VARCHAR(67), both empty by default. Dispatch derives the marker from the immutable run context; omission cannot downgrade a listed gated job. The immutable RetryPlan and complete task payload both carry the required marker and exact finite approval-wait budget. Capture compares them with the trusted policy, and the Agent recomputes the complete executable digest before preparation or startup. Pinning exact inputs and inserting the unique approval with both backlinks are one transaction. Replays retain the original expiry, content, identities, and votes.

ApprovalRequest adds nullable `retry_job_run_id` VARCHAR(64) with unique index `uk_approval_retry_job_run`, `binding_kind` VARCHAR(32), and `evidence_json` MEDIUMTEXT. `evidence_hash` expands from VARCHAR(64) to VARCHAR(67) to retain existing deployment hashes while supporting domain-separated `v1:` retry hashes. Deployment and retry backlinks must never coexist. Unknown kinds and incomplete bindings deny execution. Generic approval creation cannot manufacture a retry binding.

JobRunGeneration adds `retry_approval_admission` MEDIUMTEXT and `retry_approval_admission_digest` VARCHAR(67). The original preparation descriptor stays immutable. The distinct receipt records one exact generation, original claim, Agent, full retry plan and input/evidence identity. Its historical existence does not authorize execution: every admission and step RUNNING transition checks current authority and expiry again. Observe responses grant nothing. Terminal ACK replay remains distinct from authorization.

Review shows frozen definition/source identifiers, the complete finite attempt policy, runtime limits, all immutable registered artifact inputs and producer identities, and safe step metadata/digests. Raw command arguments, environment values and credentials are not exposed; the digest binds those executable values without displaying secrets. Definition SHA and source SHA are separately labeled. Nested historical Source Binding uses existing PascalCase JSON fields; RetryPlan policy retains existing protobuf snake_case JSON fields.

Lock ordering begins with the job and its generation/run/approval records. Scope reads consistently lock Pipeline before Project. Before touching shared permission catalogs, all participating User rows are locked in sorted order, followed by their memberships and sorted Teams; each actor callback then reuses those locks. This avoids cross-run source-only/artifact-bearing and crossed-requester/voter inversions. All authorization reads are transaction-local current reads, with post-wait expiry checks. Deployment retains its separate release-first discipline. Approval expiry is fixed once and bounded by the original job deadline and the earliest pinned artifact expiration. Cancellation preserves terminal votes and cancels only pending gates. Revocation prevents subsequent admission; it is not an assertion of instantaneous remote process termination or proof of quiescence.

There is no backfill, no automatic restart/resume, and no production enablement. Finish or cancel old in-flight jobs using compatible Agents before schema rollout. New gated jobs require matching controller/Agent protocol and explicit operator configuration. SQLite test results do not establish MySQL locking or real-container acceptance.
